# 05 — Channel merges remove the absorbed channel's verified publisher links

A duplicate-feed merge in absorb mode moves listeners from one channel to another and marks the
absorbed feed `merged`. Its verified publisher links must go with it, journaled so a revert
restores them. After the merge commits, the surviving channel is recomputed, because the
absorbed feed's URL now counts as one of its URLs (plan 02's alias rule).

## Reuses

- `selectMergeRows`, `journaledDelete`, and `sqlKey` as `moveAutoDownload` uses them in
  `applyChannelMerge.ts`.
- `revertChannelMergeJournal`, unchanged: a journaled delete is undone by inserting the row image,
  including its `id` (the column is `GENERATED BY DEFAULT`, so an explicit id is accepted).
- `ChannelVerifiedPublisherService.recomputeForChannel` from plan 02.

## Why delete and not move

A link is derived from both feeds' references; only plan 02's recompute may create one. The
surviving channel usually has a different guid, so the publisher's back-reference to the absorbed
album does not verify the survivor. Moving rows would store a link nothing verifies. Deleting them
and recomputing the survivor stores exactly what the references support.

## Changes

### `packages/orm/src/services/channel/channelMergeRowJournal.ts`

Add `'channel_verified_publisher'` to `JOURNAL_TABLES` (alphabetical, after
`'channel'`) and `channel_verified_publisher: ['id'],` to `PRIMARY_KEYS` in the same position.

### `packages/orm/src/services/channel/applyChannelMerge.ts`

1. New function after `moveAutoDownload`:

```typescript
async function removeVerifiedPublisherLinks(
  manager: EntityManager,
  channelMergeId: number,
  channelId: number
): Promise<void> {
  for (const column of ['channel_id', 'publisher_channel_id']) {
    const rows = await selectMergeRows(manager, 'channel_verified_publisher', {
      [column]: channelId,
    });
    for (const row of rows) {
      const id = sqlKey(row.id);
      if (id === null) {
        continue;
      }
      await journaledDelete(manager, channelMergeId, 'channel_verified_publisher', { id });
    }
  }
}
```

   `journaledDelete` journals only the first matching row, so delete one row at a time by `id`,
   as `moveAutoDownload` does.
1. In `applyAbsorb`, call `await removeVerifiedPublisherLinks(manager, merge.id, from.channelId);`
   directly after `await movePendingFollows(manager, merge.id, from, to);`.
1. In `verifyAndApplyDuplicateMerges`, inside the apply loop, after the
   `AppDataSourceReadWrite.transaction((manager) => applyMerge(manager, row.id))` call returns and
   before the repoint enqueue, recompute the survivor of an absorb:

```typescript
      const applied = await repo.findOne({ where: { id: row.id } });
      if (
        applied !== null &&
        applied.status === ChannelMergeStatus.Applied &&
        applied.mode === ChannelMergeMode.Absorb &&
        applied.to_channel_id !== null
      ) {
        try {
          await new ChannelVerifiedPublisherService().recomputeForChannel(applied.to_channel_id);
        } catch (error) {
          warnMerge(row.id, error);
        }
      }
```

   It runs after the commit so the recompute reads the applied merge row (the alias source). A
   failure is logged like other per-merge failures and does not undo the merge.
   Import `ChannelVerifiedPublisherService` from
   `@orm/services/channel/channelVerifiedPublisher.js`.
1. `revertChannelMerge` is unchanged: the journal restores the deleted links. Do not recompute
   after a revert; the recompute would delete restored rows whenever the references changed in
   between, and the next parse of either feed recomputes them anyway. A link the survivor gained
   only through the reverted URL alias stays until the next parse that touches it or a backfill
   run.

Repoint mode needs nothing here: it re-parses the absorbed channel's feed with `forceParse: true`,
and plan 03's parse hook recomputes it.

## Must stay true

- After an absorb, no `channel_verified_publisher` row names the absorbed channel on either side.
- A revert restores the exact rows the absorb removed.
- No `as`; rows are read through `sqlKey`.
