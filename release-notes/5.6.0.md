- Members can play on one device and control it from the web or the phone. The playing device
  publishes its item, position, and speed. Other signed-in devices show that playback and can
  pause, seek, skip, or move it. Routes live under `/account/playback`. The API requires
  `PLAYBACK_PRESENCE_LEAVE_GRACE_MS` (the base `api.env` sets 5000). An overlay that replaces the
  API env must set it
- On the phone, Next and Previous continue through a podcast, album, playlist, or Add by RSS feed,
  a finished chapter advances, and CarPlay, Android Auto, and the lock screen keep going from a
  saved list with the app closed
- Add by RSS keeps one episode across your devices. Web and the phone give those feeds their own
  pages, including music, livestreams, chapters, transcripts, downloads, and offline playback.
  Adding an artist also parses its albums. Followed feeds show their names
- Subscribed and Browse use chips, including livestreams, and the sidebar marks the current page. A
  livestream plays in the browser, including HLS where the browser can play it. The player names
  the artist with the album, a time in the notes starts playback there, and a sleep timer can stop
  it. When something cannot play, it stays in the player and the button explains why
- Notifications update while you are using the site or the app. Taste Profile is the listen opt-in.
  It builds Recommendations and, within the agreement's limits, public popularity. Sign-in is a
  server session you can review and end. Ending one closes its live account event streams, and the
  website signs out with the reason. A signed-in listener can open another account's public or
  unlisted playlist. A missing show, episode, clip, or playlist is a 404. Any other API failure on
  those pages, or on a profile, is an error page. Clips and playlist rows of a removed episode stay
  as Content Removed. A personal API key can use playlists, the queue, clips, subscriptions, Add by
  RSS, settings, notifications, and history, and it is shown once
- Operators: drop and recreate the database. Bootstrap then applies `0001_app_schema.sql` and
  `0001_management_schema.sql`. Set `API_EXPECTED_MIGRATION_FILENAME` and
  `MANAGEMENT_API_EXPECTED_MIGRATION_FILENAME` to those names. Rename
  `POPULARITY_TRACKING_AGREEMENT_VERSION` to `TASTE_PROFILE_AGREEMENT_VERSION` and
  `NEXT_PUBLIC_POPULARITY_TRACKING_AGREEMENT_VERSION` to
  `NEXT_PUBLIC_TASTE_PROFILE_AGREEMENT_VERSION` (default `2026-10-21`). Remove
  `AUTH_JWT_EXPIRATION`, `AUTH_MOBILE_ACCESS_TOKEN_EXPIRATION`,
  `AUTH_MOBILE_REFRESH_TOKEN_EXPIRATION`, and `NEXT_PUBLIC_SIDEBAR_GROUP_ORDER`. Session length is
  `AUTH_SESSION_IDLE_EXPIRATION` (31536000). Access tokens are `AUTH_ACCESS_TOKEN_EXPIRATION`
  (900). Listen records are kept `STATS_TRACK_EVENT_RETENTION_DAYS` (90). After the wipe, recreate
  the management superuser and billing rows. `BILLING_SANDBOX_GRANT_ALL=true` grants Premium for
  every sandbox purchase on a test deployment only
